# 生产部署指南

以下以同机部署 Node.js 和 Nginx 的 Linux 服务器为例。域名使用 `tryon.example.com`，应用目录使用 `/opt/3dsy`，业务数据放在 `/var/lib/3dsy`。先让域名指向服务器，并准备该域名的 TLS 证书。手机从 HTTPS 地址访问，才能正常申请相机权限。

## 1. 安装和构建

准备 Node.js 24、npm、FFmpeg（含 `libx264`）、FFprobe、Git 和 Nginx。Node.js 和媒体工具需要能被应用的服务用户找到。运行自动化测试还需要 FFmpeg 的 `lavfi` 输入和 `libvpx`、`aac` 编码器。确认数据盘可写，并为录像预留空间。默认剩余空间低于 10 GiB 时停止接受新的媒体写入。

```bash
node --version
npm --version
ffmpeg -hide_banner -encoders 2>/dev/null | grep libx264
ffmpeg -hide_banner -demuxers 2>/dev/null | grep lavfi
ffprobe -version | head -n 1

sudo useradd --system --home-dir /var/lib/3dsy --shell /usr/sbin/nologin tryon
sudo install -d -o tryon -g tryon -m 0700 /var/lib/3dsy
sudo install -d -o "$(id -un)" -g "$(id -gn)" -m 0755 /opt/3dsy
git clone https://github.com/zhimingbd55-cpu/3dsy.git /opt/3dsy
cd /opt/3dsy
npm ci
npm run build
cp .env.example .env
chmod 600 .env
npm run admin:hash
```

按提示设置一个强密码，把输出的哈希写入 `.env` 的 `ADMIN_PASSWORD_HASH`。登录时使用原密码。部署配置示例见下方，`PORT` 指本机应用端口，`PUBLIC_ORIGIN` 指浏览器访问的完整来源，域名后面不带斜杠。

```dotenv
PORT=8766
PUBLIC_ORIGIN=https://tryon.example.com
FITTING_DATA_DIR=/var/lib/3dsy
ADMIN_USER=admin
ADMIN_PASSWORD_HASH=''
FFMPEG_PATH=ffmpeg
FFPROBE_PATH=ffprobe
```

可以在后台「API 密钥」添加自己的 Decart 密钥，再设为当前。也可以通过 `DECART_API_KEY` 在空数据目录首次启动时导入。真实试衣要求账户能调用项目所用的实时试衣模型，并按 Decart 账户设置计费。只检查部署时保持密钥空白，仍可打开首页、预览相机和登录后台。移动网络需要自建 TURN 中继时，再配置与中继一致的 `TURN_HOST` 和 `TURN_SECRET`。

保存配置后将读取权限交给服务用户。可选的衣橱示例也用同一个服务用户导入，或在后台上传有权使用的服装图。

```bash
sudo chown tryon:tryon .env
sudo chmod 600 .env
sudo -u tryon npm run demo:seed  # 可选，导入五件示例服装
```

## 2. 托管 Node.js 进程

将以下内容保存到 `/etc/systemd/system/3dsy.service`。用 `command -v npm` 核对 `ExecStart` 的绝对路径，确保服务用户的 PATH 中有 Node.js、FFmpeg 和 FFprobe。

```ini
[Unit]
Description=3dsy virtual try-on
After=network.target

[Service]
User=tryon
Group=tryon
WorkingDirectory=/opt/3dsy
ExecStart=/usr/bin/npm start
Restart=on-failure
TimeoutStopSec=150
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now 3dsy
sudo journalctl -u 3dsy -n 30 --no-pager
curl -fsS -H 'Host: tryon.example.com' http://127.0.0.1:8766/api/health
```

应用监听 `127.0.0.1`，校验请求的 Host 和 Origin，并用 SQLite 持久化数据。同一份数据目录只运行一个应用实例。

## 3. 配置 HTTPS 反向代理

把下面的示例放在 Nginx 的 `http` 配置上下文中，例如从 `http` 引入的 `/etc/nginx/conf.d/3dsy.conf`。替换域名和证书路径，并与 `PUBLIC_ORIGIN` 保持一致。示例保留实时信令的 WebSocket Upgrade 和视频分段播放的 Range 请求，对分享路径关闭访问日志，因为链接本身带访问令牌。

```nginx
map $http_upgrade $tryon_connection {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    server_name tryon.example.com;
    access_log off;
    return 301 https://tryon.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name tryon.example.com;
    ssl_certificate     /etc/letsencrypt/live/tryon.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tryon.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 101m;
    proxy_http_version 1.1;
    proxy_set_header Host tryon.example.com;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $tryon_connection;
    proxy_set_header Range $http_range;
    proxy_set_header If-Range $http_if_range;
    proxy_cache off;
    proxy_force_ranges on;
    proxy_request_buffering off;
    proxy_buffering off;
    proxy_connect_timeout 5s;
    proxy_read_timeout 75s;
    proxy_send_timeout 75s;

    location ~ ^/(s/|api/shares/) {
        access_log off;
        error_log /dev/null emerg;
        proxy_pass http://127.0.0.1:8766;
    }

    location / {
        proxy_pass http://127.0.0.1:8766;
    }
}
```

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -fsS https://tryon.example.com/api/health
```

在手机打开首页并授权相机，然后到 `/admin` 登录。若接入了自己的 Decart 账户，可在有额度时发起一次试衣，检查实时连接、两路视频保存和分享回放。反代后的 403 优先检查浏览器地址、`PUBLIC_ORIGIN` 和 Nginx 转发的 `Host` 是否一致。若生成阶段断开，检查 WebSocket 升级和手机的 WebRTC 网络。若上传返回 413，核对代理的上传大小限制和应用自身的文件限制。

## 4. 备份和升级

- 先在后台暂停新试衣，等当前会话结束，再停止服务。将整个 `FITTING_DATA_DIR` 备份到受限目录，保留 SQLite、媒体和隐藏的 `.secrets/`。密钥与分享链接的解密需要其中对应的文件。
- 将 `.env` 单独放入受限备份。它可能含管理员密码哈希、Decart 或 TURN 凭证。分享链接和录像也应按业务数据管理。
- 升级前记录当前 Git 提交，在新版本运行 `npm ci`、`npm run build` 和 `npm test`，再用原数据目录启动。验证后在后台恢复试衣接入。需要回退时，先保留故障时的数据副本，再确认旧版本与当前数据库兼容，或恢复到同一时间点的一组备份。

```bash
sudo systemctl stop 3dsy
sudo sh -c 'umask 077; tar -C /var/lib/3dsy -czf "/var/backups/3dsy-$(date +%F-%H%M%S).tar.gz" .'
sudo systemctl start 3dsy
```
